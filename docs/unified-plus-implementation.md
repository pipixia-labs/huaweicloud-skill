# 大一统 Plus 实施状态

本文记录基于 v0.9.1 开始的 Plus 实际实施、行为证据、Stop/Go 决定和未实施项。它不是未来
规划的重复说明，也不把静态契约测试写成 Agent 已经采用机制的证据。

## 1. 实施方法和边界

每个切片都使用相同方法：冻结 v0.9.1 直接基线，固定 Agent、模型、工具权限、task workspace、
逐轮输入和 L0 fixture；先重复运行直接基线，再只改变一个候选机制，并同时记录目标质量、
task 采用、完成准确性、自主性、安全硬失败、文件、工具调用和耗时。

当前仍坚持：

- Skill 提供知识、共享语义和任务记忆方法，不控制 Agent 的服务、工具、参数或调用顺序；
- CloudClaw 只作为行为评测器，不为评测修改平台代码；
- 评测用户没有华为云凭证，不调用真实云或网络工具；
- 简单任务保持轻量，大输出保护和 v0.8.2 操作清单保持不变；
- 小样本结论只适用于已覆盖的 Agent、模型、workspace 和场景。

## 2. 已保留：可移植任务描述符

v0.9.1 直接基线的 15 个复杂任务都能写入任务记忆，但平台内部 conversation/task_run ID 对
Agent 不可见。把该结果直接判成 Agent 不遵守不合理，因此增加以下可移植语义：

- 运行时 ID 对 Agent 可见时原样保存；
- 不可见时，复杂任务首次建档生成稳定描述符并写明来源；
- 后续轮次从任务入口复用；
- 描述符不冒充平台 ID，也不用于平台 API。

第一候选只把说明追加到长段落，采用率仍为 0/3。第二候选把非空 `task_id` 和
`task_id_source` 提升为复杂任务建档的首句验收条件，采用和跨轮复用均为 3/3；简单 B1
查询仍为 0 个正式任务文件和每次 3 个工具调用，安全硬失败为 0。因此保留第二候选，不继续
扩展身份 Schema。

这证明的是当前条件下“少数恢复必需信息需要高显著性验收”有效，不代表任何 Agent 都必然遵守。

## 3. 已停止：三目标单文件扩展

Plus 切片 1 为跨服务资源盘点和成本治理增加了两个固定 L0 行为场景。v0.9.1 直接基线显示：

| 场景 | 直接基线 | 主要缺口 |
| --- | --- | --- |
| 跨服务资源盘点 E1 | 目标完整率 21/24；覆盖、失败、分页、未查询、大输出和部分完成均稳定 | enterprise project 作用域 0/3 |
| 成本治理 E2 | 目标完整率 30/30；账单语义、候选证据和未来节省不确定性均完整 | 当前 rubric 无可计分缺口 |

随后在一个文件中增加资源盘点和成本治理目标内容，并在 `SKILL.md` 增加可选导航。E1 重复
3 次后：

- 目标完整率仍为 21/24，enterprise project 作用域仍为 0/3；
- 新目标指南实际读取为 0/3；
- task 落盘从直接基线 3/3 降为 2/3；
- 工具调用中位数从 6 增至 7，安全硬失败仍为 0。

候选没有收益且出现一次既有机制退化，因此按 Stop 条件撤回新增目标内容和 SKILL 导航，不再
通过更强措辞迫使 Agent 读取。E2 直接基线已经达到当前 rubric 上限，未继续运行无因果价值的
候选重复。

保留下来的是 E1/E2 评测场景、直接基线和失败样例。这个结果说明“大 Skill”不能靠继续增大
共享文档获得优势；目标内容只有被 Agent 实际按需加载并改善遗漏时才值得保留。

## 4. 当前行为证据

当前结果目录共保存 36 份逐次运行记录：

- 切片 0 的 v0.9.1 直接基线 18 次；
- 任务描述符候选 1 和候选 2 各 3 次复杂任务；
- 候选 2 的简单查询回归 3 次；
- 切片 1 的 E1/E2 直接基线各 3 次；
- 切片 1 已停止候选的 E1 3 次。

所有评测都保留 run metadata、最终回复、工具轨迹和正式 workspace 文件清单。A4 的真正
context 清空恢复仍为 `not_observable`，不能用普通下一轮对话冒充。

## 5. 未实施项

当前没有实施：

- 全量 CapabilityGraph 或第二套服务事实源；
- 固定 TaskContract/TaskPlan/TaskEvent/EvidenceRecord 对象；
- Goal、Option、Progress、Recovery、Completion 五个强制文件；
- Policy Engine、Execution Gateway 或固定状态机；
- workload、长期偏好和跨 Agent 机器交换格式；
- 针对 CloudClaw 的环境变量或平台代码绑定。

## 6. 验证

当前稳定内容通过：

```bash
python -m unittest tests.test_unified_mechanism_contracts
python -m unittest discover -s tests
ruff check .
python -m compileall -q scripts tests
git diff --check
```

最近一次候选静态门禁为 431 tests passed、10 skipped；撤回无收益目标内容后需要再次运行最终
门禁，以最终工作树结果为准。

## 7. 下一步

下一切片不再继续堆目标卡。优先评审“证据、恢复和用户表达”是否存在能用直接基线暴露的具体
缺口，再决定是否增加轻量投影指南。任何新内容仍需回答：谁会读取、不记录会造成什么错误、
能否被多个场景复用，以及收益是否大于上下文和自主性成本。
