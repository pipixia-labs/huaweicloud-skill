# 大一统 Plus 实施状态

本文记录基于 v0.9.1 开始的 Plus 实际实施、历史行为证据、当前待验证内容和后续建设项。它不是
未来规划的重复说明，也不把架构完成或静态契约写成 Agent 已经采用机制的证据。

当前范围限定为一个对话/task 内的多轮、跨服务和跨场景一致性。task 内部可由 Agent 自主组织为
`phase -> step -> operation`，subtask 可选；不建设跨 task workload、长期偏好、跨 Agent
交接、常见 Agent 适配或 P2 扩展。

## 1. 实施方法和边界

切片 0、任务描述符和目标能力候选曾使用固定条件的重复行为评测。自 Plus 切片 2 起，按用户要求
调整为“先依据已确认架构完成实现，再由用户负责测试和优化”：实现阶段不再由 Codex 的评测目标、
Stop/Go 或小样本结果裁剪模块。未经用户测试的新增内容明确标记为待验证，不对外宣称已经产生
行为收益。

当前仍坚持：

- Skill 提供知识、共享语义和任务记忆方法，不控制 Agent 的服务、工具、参数或调用顺序；
- 使用本 Skill 的 Agent 假定具备 Skill 使用、代码执行、云工具调用和 workspace 文件读写能力；
- CloudClaw 只作为行为评测器，不为评测修改平台代码；
- 评测用户没有华为云凭证，不调用真实云或网络工具；
- 简单任务保持轻量，大输出保护和 v0.8.2 操作清单保持不变；
- 小样本结论只适用于已覆盖的 Agent、模型、workspace 和场景。

## 2. 已保留：可移植任务描述符

v0.9.1 直接基线的 15 个复杂任务都能写入任务记忆，但平台内部 conversation/task_run ID 对
Agent 不可见。把该结果直接判成 Agent 不遵守不合理，因此增加以下可移植语义：

- 运行时 ID 对 Agent 可见时原样保存；
- 不可见时，复杂任务首次建档生成稳定描述符并写明来源；
- 后续轮次从任务入口复用；
- 描述符不冒充平台 ID，也不用于平台 API。

第一候选只把说明追加到长段落，采用率仍为 0/3。第二候选把非空 `task_id` 和
`task_id_source` 提升为复杂任务建档的首句验收条件，采用和跨轮复用均为 3/3；简单 B1
查询仍为 0 个正式任务文件和每次 3 个工具调用，安全硬失败为 0。因此保留第二候选，不继续
扩展身份 Schema。

这证明的是当前条件下“少数恢复必需信息需要高显著性验收”有效，不代表任何 Agent 都必然遵守。

## 3. 已恢复为可选资料：三目标单文件扩展

Plus 切片 1 为跨服务资源盘点和成本治理增加了两个固定 L0 行为场景。v0.9.1 直接基线显示：

| 场景 | 直接基线 | 主要缺口 |
| --- | --- | --- |
| 跨服务资源盘点 E1 | 目标完整率 21/24；覆盖、失败、分页、未查询、大输出和部分完成均稳定 | enterprise project 作用域 0/3 |
| 成本治理 E2 | 目标完整率 30/30；账单语义、候选证据和未来节省不确定性均完整 | 当前 rubric 无可计分缺口 |

随后在一个文件中增加资源盘点和成本治理目标内容，并在 `SKILL.md` 增加可选导航。E1 重复
3 次后：

- 目标完整率仍为 21/24，enterprise project 作用域仍为 0/3；
- 新目标指南实际读取为 0/3；
- task 落盘从直接基线 3/3 降为 2/3；
- 工具调用中位数从 6 增至 7，安全硬失败仍为 0。

候选没有收益且出现一次既有机制退化，因此当时按 Stop 条件撤回新增目标内容和 SKILL 导航，
没有通过更强措辞迫使 Agent 读取。E2 直接基线已经达到当前 rubric 上限，未继续运行无因果价值
的候选重复。

后续经用户明确决定，三目标指南和 `SKILL.md` 可选导航作为目标组织参考资料恢复保留，同时增加
来源映射和静态契约。该决定不改写既有行为证据：新增指南当时仍为 0/3 实际加载，尚未证明改善
Agent 行为，也不构成对所有任务强制读取的要求。后续只有出现新的可观察收益，才能把它表述为
Plus 已验证优势。

E1/E2 评测场景、直接基线和失败样例继续保留。这个结果仍说明“大 Skill”不能只靠增大共享文档
获得优势；可选目标资料的实际采用、收益和上下文成本需要继续观察。

## 4. 已实施、待用户验证：证据、恢复和用户表达

Plus 切片 2 已把 Goal、Option、Progress、Recovery 和 Completion 实现为从同一份 task 记忆
按需生成的用户视图：

- `references/interaction-guidance.md` 说明五种视图的适用时机、最少信息、证据边界和避免过度播报的方法；
- `templates/task.md` 可选记录完成条件、证据状态/来源/时间/作用域和未知或遗留事项；
- `templates/progress.md` 只保留重要阶段、证据、阻塞、用户影响和下一步；
- `references/task-workspace-guide.md` 明确五种视图不是五个文件或固定 Schema；
- `SKILL.md` 在方案选择、阶段进展、失败恢复、部分成功、结果未知和完成交付时提供按需导航；
- `references/source-map.md` 把交互指南归为跨服务编写知识，不把它当作服务事实源、授权账本或状态机。

Agent 仍然决定使用哪些视图、服务、工具、参数、顺序和表达形式。简单任务不要求完整投影；恢复
任务或继续高影响操作前，task 记忆中的易变事实需要重新查询。

本切片按用户要求未运行单元测试、行为评测或 Stop/Go 判断，当前状态是“架构内容已实施，等待
用户测试和优化”。

## 5. 已实施、待用户验证：知识管线和渐进披露

Plus 切片 3 在现有 `references/source-map.md` 中实现知识所有权和分层加载，不新增复杂上下文
路由器或第二套事实数据库：

- 把内容区分为权威事实、编写知识、派生视图和运行时事实，并分别指定权威位置和维护规则；
- 明确 registry、catalog、router、guide、playbook、task/artifact 之间的单一事实来源关系；
- 实现 Metadata、`SKILL.md`、Shared Core、Goal/Scenario、Service Module 和 Materials 六层加载路径；
- 定义何时停止扩大上下文、何时因跨服务目标、证据缺口或来源冲突继续加载；
- 规定大输出仍进入 artifact，不因“加载更多知识”重新塞入对话；
- 补充新服务模块接入共享体系时要说明的目标、来源、复用、差异、覆盖和引用；
- 补充真实经验从 task 个案经过脱敏、归因和人工评审后晋升共享知识的路径；
- 为高影响或易漂移知识提供来源、作用域、版本、覆盖、缺口和替代关系的轻量维护建议。

`SKILL.md` 的资料入口同步改为“知识所有权、渐进加载和材料溯源”。该加载路径是知识导航，不是
Agent 的固定执行流程；Agent 可以根据现场选择其他合理资料和工具。

本切片按用户要求未新增或运行测试，当前状态是“知识管线已实施，等待用户测试和优化”。

## 7. 明确不实施的能力

以下内容不属于当前跨场景一致性目标，也不作为条件性后续 TODO：

- 全量 CapabilityGraph 或第二套服务事实源；
- 固定 TaskContract/TaskPlan/TaskEvent/EvidenceRecord 对象；
- Goal、Option、Progress、Recovery、Completion 五个强制文件；
- Policy Engine、Execution Gateway 或固定状态机；
- 跨 task workload、长期偏好和隐式画像；
- 跨 Agent 交接和机器交换格式；
- 常见 Agent 或特定框架适配层；
- P2 能力扩展；
- 针对 CloudClaw 的环境变量或平台代码绑定。

CCI、CCE 和 Kubernetes 资料中的 workload 是容器工作负载技术术语，不受上述范围收口影响。
