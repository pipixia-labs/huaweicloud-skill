# 目标—能力组织样例：企业网站上云

## 这份样例解决什么问题

当用户说“把企业网站部署到华为云”时，目标往往同时涉及运行载体、网络入口、域名、HTTPS、数据、监控、日志、备份和成本。单独从某个服务出发容易遗漏目标，也容易过早锁定一种实现。

本文件演示如何围绕用户目标组织现有资料。它提供候选能力、替代路径、澄清点和验收维度，**不是唯一方案**，也不替代场景路由、实时发现、安全确认或 Agent 的判断。

## 目标摘要

典型目标可以表达为：

> 在满足网站类型、访问范围、预算和运维要求的前提下，选择可落地的华为云能力，并以用户可访问、证书有效、关键业务路径正常且可观测为完成依据。

先保留会显著改变架构的要求：

- 网站是纯静态、服务端渲染，还是 Java/其他动态应用；
- 是否需要数据库、持久文件、定时任务或后台管理；
- 目标 region、访问用户和备案等外部条件；
- 域名是否已有、由谁管理，是否要求 HTTPS；
- 可接受的持续费用、可用性、恢复目标和运维复杂度；
- 当前只需要方案，还是后续可能执行真实部署。

## 候选能力

| 目标维度 | 候选能力 | 替代路径或影响因素 |
| --- | --- | --- |
| 静态内容托管 | OBS 静态网站等对象存储能力 | 若存在 Java、会话或服务端逻辑，应转向计算类载体；也可使用已有外部构建/托管能力 |
| 动态应用运行 | ECS、Flexus、容器等计算候选 | 根据应用形态、团队经验、弹性、运维和当前 region 可用性选择 |
| 公网入口 | EIP、负载均衡、CDN 或服务自带入口候选 | 流量、源站类型、安全暴露、缓存和高可用要求会改变选择 |
| 域名解析 | DNS 与现有域名管理能力 | 域名可能由外部注册商管理；需明确变更权限和生效验证方式 |
| HTTPS | 证书管理、负载均衡/CDN/源站 TLS 能力 | 证书来源、绑定位置、续期方式和域名控制权需要确认 |
| 数据能力 | RDS 等托管数据库或用户已有数据库 | 取决于应用依赖、兼容性、网络、备份和费用；纯静态站通常不需要 |
| 日志与指标 | LTS、CES、应用自身日志和健康检查 | 先明确希望观察的用户路径、指标、日志范围和保留周期 |
| 备份与恢复 | 服务自带备份、CBR、对象版本或应用级备份候选 | 恢复目标、数据位置和演练要求决定方案 |
| 成本与治理 | 规格、计费方式、标签、预算和账单查询能力 | 实时报价、优惠和当前租户条件应查询，不能仅凭资料推断 |

Agent 应先通过路由和当前上下文缩小候选，再针对关键缺口查询。表格不规定服务组合，也不规定各操作的先后关系。

## 替代路径示例

### 路径 A：纯静态企业展示站

可从 OBS 静态托管、域名、HTTPS、缓存和基础可观测能力中组合候选。若用户后来要求 Java 后端、数据库或服务端会话，这条路径不再满足当前目标，应重新选择运行载体。

### 路径 B：单体 Java 应用

可从计算实例或适合的容器运行能力、数据库、网络入口、域名/HTTPS、日志与监控中组合候选。规格、网络结构和部署工具由实时条件及 Agent 判断，不在本样例中预设。

### 路径 C：已有运行环境，只补齐上线能力

如果用户已经有计算、应用或数据库，重点可能变成入口、域名、HTTPS、观测和验收。不要因为“网站上云”重新创建已有资源。

## 只问会改变方案的问题

优先澄清以下问题；已有可靠答案时不要重复提问：

1. 网站是否包含必须在服务端运行的动态能力？
2. 是否已有应用、数据库、域名、证书或云资源需要复用？
3. 目标 region、访问范围和预算边界是什么？
4. 用户当前授权范围是仅规划、只读预检，还是在看过方案后允许执行？
5. “上线完成”的关键用户路径和可用性要求是什么？

## 已知缺口和动态事实

以下内容通常不能从本文件直接得到：

- 当前账号、project、region 的服务和 API 可用性；
- 配额、权限、已有 VPC/子网/安全组、域名和证书状态；
- 当前规格、价格、优惠、备案和外部 DNS 条件；
- 应用真实依赖、构建产物、健康检查和数据迁移方式；
- 用户是否已经看过本次方案并明确授权真实变更。

这些缺口由 Agent 通过提问、现有脚本、工具观测或官方资料补齐。遇到未预见的服务限制时，应保留目标并寻找替代能力，而不是坚持初始候选。

## 完成和证据

不同方案可以共享以下验收思路：

- 架构和费用风险已经向用户说明，真实变更得到当前方案的明确授权；
- 云资源达到所需状态，但这只说明 `resource_ready`；
- 域名解析、TLS、HTTP/应用健康和关键业务路径获得相应证据；
- 监控和日志能覆盖约定的关键路径；
- 未验证、部分成功或结果未知的内容被明确列出。

不要把资源创建成功、任务已受理或单个 HTTP 状态自动写成网站整体完成。
